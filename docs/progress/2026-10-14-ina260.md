## Why a separate driver

INA219 and INA260 use different registers and scaling. The INA219 driver cannot be used unchanged.

INA219 needs an external shunt and calibration. INA260 has an integrated shunt and fixed scaling. Its current register is `0x01`; INA219 uses `0x04`.

## V5c connections

Taken from the published V5c PCB. Not yet checked on hardware.

| Setting | Value |
| --- | --- |
| Controller | I2C1 |
| SDA / SCL | GPIO2 / GPIO3 |
| Bus speed | 100 kHz requested |
| U26 | Address `0x40`; `Dir_Chrg_In` → `VBATT_SENSE` |
| U3 | Address `0x41`; `VSOLAR` → `V_SYS` |
| ALERT | Unconnected; readiness is polled |

Addresses are 7-bit. The sample disables the inherited INA219 nodes and adds `ti,ina260` nodes on I2C1. The driver gets its bus and address from devicetree.

## Driver behaviour

Checks manufacturer ID `0x5449` and die ID `0x227x`.

A fetch writes `0x6123` to configuration register `0x00`. This starts one current/voltage measurement, with 1.1 ms per conversion. It checks the configuration readback, then polls for readiness with a 20 ms deadline. I2C transaction timeouts are separate.

| Register | Reading | Scale |
| --- | --- | --- |
| `0x01` | Signed current | 1.25 mA/count |
| `0x02` | Bus voltage | 1.25 mV/count |
| `0x03` | Unsigned power | 10 mW/count |

Values are cached only after all reads succeed. A failed fetch marks the sample invalid. Getters return cached values without more I2C traffic. One task should own the fetch/get sequence.
